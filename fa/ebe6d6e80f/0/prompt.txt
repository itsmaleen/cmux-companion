Nested scrolling was ruled out because SwiftTerm's `TerminalView` **is itself a `UIScrollView`**, and two nested vertical scrollers fighting the same pan gesture was not solvable within reasonable effort.

**Deviations from the brief (both necessary, both verified working):**
1. **SwiftTerm pinned to 1.18.0**, not latest (1.20.0): 1.19+ added `SwiftTermBuildInfoPlugin`, a build-tool plugin whose executable dependency this toolchain builds under `Debug-iphonesimulator/` while the plugin looks for it under `Debug/` — always fails. 1.18.0 predates the plugin and has every API used here.
2. **Build must use `-scheme cmux`, not `-target cmux`.** This project's mandated `-project ... -target cmux ...` (no `-scheme`) never uses DerivedData for its own build products (confirmed: `xcodebuild -derivedDataPath ... -target ...` itself refuses, "requires -scheme"), and Xcode's SPM package-product integration (`PackageFrameworks`) only populates under DerivedData. With `-target` only, `cmux` intermittently/consistently fails `error: no such module 'SwiftTerm'` / `unable to resolve module dependency`. `-scheme cmux` (auto-generated by xcodegen, same target) builds reliably every time. `screenshots.sh` uses `-scheme`; documented inline there and in `project.yml`.
3. **Landscape screenshots dropped** — attempted per spec, but `simctl io screenshot` captures the simulator's fixed portrait-shaped framebuffer, so the geometry request just rotates content sideways inside a portrait canvas rather than yielding a real landscape image. Portrait-only, per the brief's own fallback.
